# pointp.dev トップページの仕様

ドメイン名にちなんで、「動く点P」で一筆書きの絵や文字を描けるページにする。

## 概要

- 点P はいつも動き続けていて、通ったあとに線（軌跡）が残る
- ユーザーは点P の進む方向だけを変えられる。止められないので、思いどおりに描くのは難しい。その難しさも遊びにする
- 線はすべて一筆書きになる（線を書かずに動く機能は作らない）

## 操作

- 画面上のジョイスティックで方向を変える。キーボードでは操作しない
- 方向は無制限（8 方向に限らない）。曲線も描けるようにするため
- PC とスマホのどちらでも、同じジョイスティックで操作できる
- 見た目は野暮ったくならないようにする。ジョイスティックだと直感的に分かり、方眼や線と調和するデザインにする
- ジョイスティックの位置は下の中央に固定する。下の余白は safe-area を考慮する（iPhone のホームバーと重ならないように）
- 大きさは画面によらず固定。台の直径 128px、ノブの直径 44px（指で押しやすい最小の大きさ）
- ノブが目盛りに重ならないよう、ノブの中心が動ける範囲は、目盛りの内端からノブの半径を引いた所まで（台の中心から 32px）。向きは指の位置で決めるので、指はノブより外へ動かしてよい（試作で確認）
- ノブの色は今のインクの色にする
- 台は分度器をモチーフにする（ふちに目盛り、x・y 軸）。進む向きの矢印（ベクトル）は表示しない
- ジョイスティックに触っている間だけ、点P が進む向きに近い目盛りの色を変える。指を離したら元に戻す（試作で確認）
- ノブは指の位置についていき、円のふちで止まる
- 点P の向きには、中心から見たノブの角度だけを使う。ノブを動かすと、すぐにその角度へ向きを変える。傾けた量は使わない
- 中心の近く（指の位置が台の半径の 2 割ほど）は遊びにし、向きを変えない（わずかな指のずれで向きが大きく振れないように）
- 指を離すとノブは中心に戻る。点P は最後の向きのまま進み続ける

## 世界とカメラ

- 点P を画面の中心に固定し、背景（世界）が動く
- 点P のすぐ右上に「P」の文字を表示する。点P と同じく紙の色の縁取りを付ける（線が重なっても読めるように）
- 「P」の文字は、自己紹介を書いている間は出さず、ジョイスティックと同じタイミング（1 秒）でふわっと出す（試作で確認）
- 世界の広さには限りがある
- 世界の端は上下・左右でつながっている（右端へ進むと左端から出てくる）
- 世界を上下左右に敷き詰めて描画する。端の先には反対側の続きが見え、端をまたいでも背景や線が途切れない
- 世界の境目には薄い線を引き、端の位置が分かるようにする
- 世界は正方形。1辺は、ページを開いた時点の画面の長い辺の約 2.5 倍。そのあとは変えない（スマホを回転しても窮屈にならないように）
- 世界の1辺は、方眼の5マス分（太い線の間隔）の倍数に丸める。世界の境目を方眼の太い線にそろえるため
- 世界の大きさには上限を設ける（大きな画面でメモリを使いすぎないように）
- 回転やリサイズでは世界を変えず、見える範囲だけを変える
- 世界は画面より大きくする（同じ線が1つの画面に2つ映らないように）。画面が世界より大きくなったときは、拡大して表示する
- 点P のデフォルトの速さ（1 秒に進む px）は、世界の1辺に対する割合で決める。1 秒で世界の1辺の 1/20 進む（一周 20 秒。試作で確認。はじめの 16 秒は少し速かった）
- 速さは 5 段階。倍率は ×0.5 / ×0.7 / ×1（デフォルト）/ ×1.4 / ×2。1 段階ごとに約 √2 倍にし、変化の感じ方をそろえる
- いちばん速い・遅い段階で、さらに加速・減速のポイントを通っても何も変わらない
- 値は試作で動かして調整する

## ミニマップ

- 画面の右上に置き、世界全体のどこに線を描いたかと、点P の現在地が分かるようにする（将来ハンバーガーメニューを置くなら左上にし、ぶつからないようにする）
- 端からの余白は safe-area を考慮する（スマホのノッチなどに隠れないように）
- 世界全体を1枚だけ縮小して表示する（敷き詰めない）。表示する位置は固定で、点P に合わせて動かさない
- 表示するもの: 描いた線、点P の現在地、今見えている範囲の枠、ポイントの位置
- 正方形で、大きさは画面に合わせて 144〜200px の間で変える（試作で確認。はじめの 96〜160px から 1.5 倍にし、PC では大きすぎたので最大を 200px にした）
- 台はジョイスティックと同じ質感（透けない紙色・枠線・角丸・薄い影）。中に方眼は描かない
- 線はそれぞれのインクの色（最小 1px）。点P は今のインクの色の点に紙の色の縁取り。見えている範囲は点線の枠
- ポイントは灰色の小さな点。全消去だけは黄色にして、注意マークとそろえる（危険な場所が地図でも分かるように）
- 見るだけで、触っても何も起きない
- 点P は、ミニマップの上では右端から左端へ移る
- 見えている範囲の枠が世界の端をまたぐときは、枠をミニマップの左右（上下）に分けて表示する

## 最初の流れ（自己紹介）

1. ページを開いたら、すぐに点P が英語の自己紹介を書き始める。全文を目の前で一筆書きで書く
2. 書き終わったら、ジョイスティックが現れて、ユーザーが操作できるようになる

- 開いた時点では、カメラを引いて（縮小して）自己紹介の全体を画面に収める（スマホでも全文が読めるように）
- 全文を約 5 秒で書く（試作で確認。これより短いと何を書いているか分かりにくい）。そのため、自己紹介を書く間の速さはデフォルトの速さとは別に決める（自己紹介を書く速さは約 1270px/秒。デフォルトの約 8 倍（PC）〜約 12 倍（スマホ））
- 自己紹介の大きさは、字の大きさで決める。小文字の高さを、デフォルトの線の太さの約 3.5 倍（約 42px）にする（横幅は約 1280px）。世界の大きさで決めると、世界が小さいスマホほど字に対して線が太く見えるため（試作で確認）
- ただし、横幅は世界の1辺の 60% までにする（とても小さい画面で、ポイントを置く場所がなくならないように）
- 書き終わったら、カメラが 1 秒かけて点P に寄り、通常の大きさに戻る（試作で確認）。同時にジョイスティックとミニマップが現れる
- 点P の速さは、書き終わってから 0.3 秒でデフォルトの速さへ落とす（はじめに大きく落ちる ease-out）。カメラが寄る 1 秒より短くするのは、速いまま進んで自己紹介がすぐ画面から外れないようにするため（試作で確認）
- 動きを減らす設定の人（`prefers-reduced-motion`）には、書くアニメーションをせず、全文を書き終えた状態から始める
- 書いている間は、ジョイスティックもミニマップも出さず、線と点P だけにする
- 書き終わったら、ジョイスティックとミニマップが同時に、カメラが寄るのと同じ 1 秒でふわっと現れる（ジョイスティックは下から少し浮き上がる）
- 現れた直後に、ジョイスティックで向きを変えられることを、文字を使わずに見せる（試作で確認）
  - ノブが点P の進む向きへ 14px 押し出されて戻るのを、1.1 秒で 2 回くり返す。その間は向きの目盛りをインクの色で光らせる。今の向きと同じ方向へ動かすので、点P の進み方は変わらない
  - 8 秒たっても触らなければ、もう 1 回だけ見せる
  - 一度でもジョイスティックに触ったら、その場でやめ、次の訪問からも見せない（localStorage に記録する。使えない環境では毎回見せる）
  - 動きを減らす設定では、ノブは動かさず、目盛りだけを光らせる
- 自己紹介の線の最後は、最後の文字「g」から下へ回り込み、2 行目の下を左へ向かう。点P はこの向きのまま、下線を引くように自己紹介の下を左へ進み続ける（すぐ自己紹介が画面から外れないように）。ユーザーがすぐ操作しなくても描き続ける

- 自己紹介は手書き風の一筆書きの線にする。線の太さはすべて同じ
- 文面は 2 行で、1 行目 `I'm pointp`、2 行目 `Always moving`。カンマは付けない（改行が区切りの役目をする）。名前はドメイン名と同じくすべて小文字
- 2 行にするのは、カメラを引いたとき縦向きのスマホでも文字を大きく見せるため（1 行の約 2 倍）
- 2 行目は右へずらす。1 行目の終わりから 2 行目へは、A の書き始め（左下）の向きに沿って入る（A を横切るが、読むのに支障はない）
- 文字の形は Hershey フォントの cursive（パブリックドメインの一筆書き用フォント）を元にする。ペンを離す所（単語の間など）は、線の向きに沿った曲線でつないで 1 本の SVG パスにする。単語の間は、ベースラインの下へ少したわませてつなぐ
- 正確な筆記体より、読みやすさを優先する。アルファベットにない線（ペンを離す所をつないだ線、文字の中の余分なループ）が出る文字は、形を差し替える（試作で確認）
  - t の横棒・i の点・I' のアポストロフィは、書く途中で寄り道して、同じ線をなぞって戻る（行き来する線を出さない）
  - o・a・g・m・n・p・s・v・w は、余分なループ・くぼみや丸の中を通る線が出ないように書き方を変える
  - 書き方を変えて文字の間隔がそろわなくなった所は、文字の組ごとに間隔を調整する（例: p と o の間を詰める）
  - o・v・w のあとは上（てっぺんの高さ）でつなぎ、次の文字の下からの入りの線は省く（つなぎ目に折り返しができないように）
  - 下で払って終わる文字のあとは、次の文字の入りの線の書き始めの点を省き、払いからそのまま入りの線へ流す（右上がりの線どうしを短い横線でつなぐとジグザグに折れるため）
  - A は筆記体の雰囲気を残しつつ簡単にし、横棒は右上がりに傾け、l との間をあける。I と A は活字の形にはしない（ほかの筆記体の文字と合わないため）
- パスは [tools/intro/build.mjs](../tools/intro/build.mjs) で生成する（`npm run intro`。点P が書くための曲線のデータ `src/intro-data.js`、`noscript` 用の `src/public/intro.svg`、確認用の `tools/intro/intro.svg` を書き出す）。使う文字だけのフォントデータは [tools/intro/cursive.json](../tools/intro/cursive.json)、差し替える文字は [tools/intro/readable.json](../tools/intro/readable.json)（差し替える理由も書いてある）

## ポイント

キャンバス上に、点P が通ると効果が出るポイントを置く。

| ポイント | 効果 |
|---|---|
| 色（インクの色ごとに1種類） | 線の色がその色に変わる |
| 太く | 線の太さが1段階上がる |
| 細く | 線の太さが1段階下がる |
| 加速 | 点P の速さが1段階上がる |
| 減速 | 点P の速さが1段階下がる |
| 全消去 | 描いた線をすべて消す。自己紹介も消え、書き直さない |
| 保存 | 世界全体の線の状態を、方眼の背景ごと PNG 画像でダウンロードする。ポイントは含めない。ファイル名は保存した日時付き（例: `pointp-20261105-142530.png`）。ジョイスティックに触ったあとの 1 回だけ効く（下の決まりを参照） |

- 保存は、ジョイスティックに触ってからでないと効かない。保存したら、もう一度触るまで効かない（触り続けたまま通っても効かない）。点P は止まらず同じ道を通るので、放っておくとファイルが落ち続け、ブラウザに連続のダウンロードとして止められるため。効かないときも、スタンプが沈む反応は出す
- 色は値ごとに別のポイントにする。太さと速さは、上げる・下げるの2種類にする（アイコンから動作が分かりやすいように）

- 配置はランダムに散らす。絵を描けるのは副次的なものなので、探索の楽しさを優先する
- ページを開くたびに配置を変える
- 自己紹介の線と重ならないように置く
- 同じ種類のポイント（2 個ずつある太く・細く・加速・減速）どうしは、世界の1辺の 40% 以上離す（同じものが近くに並んでも意味がないため）
- ポイントどうしは、世界の1辺の 12% 以上離す。世界の端はつながっているので、端をまたいだ距離も含めて測る
- 置き方: ランダムに場所を選び、条件を満たさなければ選び直す
- 全消去は、自己紹介から世界の1辺の 25% 以上離す（書き終えた点P がそのまま進んで、操作する前に自己紹介を消してしまわないように）
- 数は合計 15 個: 色は各 1 個（5 個）、太く・細く・加速・減速は各 2 個（8 個）、全消去 1 個、保存 1 個
- 取っても消えたり移動したりしない
- 通るたびに効果が出る
- 触れている間に何度も切り替わらないように、一度離れるまでは反応しない
- 当たり判定は、見た目の円と同じ大きさにする
- 色と太さは、ポイントを通った瞬間に切り替わる（グラデーションにはしない）
- 通ったときに文字などは表示しない。代わりに、世界の中の動きで応える（試作で確認）
  - どのスタンプも: 押し直したように沈む（0.09 秒で 82% まで縮み、0.27 秒で戻る）。押した瞬間は縁を今のインクの色にする
  - 保存: 画面全体が、シャッターのように一瞬白く光る（0.45 秒。すぐ明るくなり、ゆっくり戻る）
  - 全消去: 線が 0.5 秒かけて、かすれた点線になりながら薄く細くなって消える（消しゴムでこすったように）
  - 加速・減速: 速さが変わった瞬間だけ、点P が進む向きに伸びる（加速）か、つぶれる（減速）。0.08 秒で変形し、0.32 秒で丸に戻る。それ以上速さが変わらないときは何も起きない
  - 動きを減らす設定（`prefers-reduced-motion`）では、形や位置の動きを小さくし、何が起きたかは明るさと色で伝える（スタンプは縁の色だけ変える、保存の光は弱く短く、全消去はかすれずに薄くなる、加速・減速は点P の縁取りを一瞬インクの色にする）

### 見た目

- スタンプ風: 二重の丸を、インクで押したような見た目にする。1つずつ少し傾けて、手で押した感じを出す
- 中は紙の色で塗り（100%）、線より上に描く（線が重なってもアイコンが読めるように）
- 点P が触れても透けさせない（試作で確認。透ける処理はなくてよい）
- 色のポイントは、丸の中をその色で塗る。ほかのポイントは、種類を表すアイコンを入れる
  - 太く・細く: 線と上下の矢印（太くは、太い線を外向きの矢印で広げる。細くは、細い線に内向きの矢印を押し当てる）。56px のスタンプでも読めるよう、線と矢印は太く、矢じりは大きくする
  - 加速・減速: メーター（針が右へ振れると加速、左へ振れると減速）。針の側の弧を太くし、針の向きだけでなく形でも見分けられるようにする
  - 全消去: ゴミ箱
  - 保存: 下向きの矢印と受け皿（ダウンロードの形）
- 全消去は取り消せないので、右上に注意マーク（黄色の三角）を付ける

## デザイン・配色

見た目の見本は [design-mock.html](design-mock.html)（ブラウザで開く）。

- AIの既存知識に頼らず、デザインや配色のサイトを参考し、シンプルかつ見た目にこだわったサイトにする
- デザイントークンなどを決め、統一されたデザインにする
- 方向性は方眼ノート風（薄い方眼の背景に、インク色の線）
- カメラを引いている間は、方眼の細い線を倍率に合わせて薄くする（最小 25%）。マス目が詰まって、字より方眼が目立つため
- 点P・「P」の文字・ジョイスティックのノブ・向きを示す目盛りは、すべて今のインクの色にする（「今のペン」という1つの状態にまとめる）
  - 点P には紙の色の縁取りを付け、同じ色の線に埋もれないようにする
  - 向きを示す目盛りは、色だけでなく太くして区別する（ブルーブラックやセピアは灰色の目盛りとの差が小さいため）。長さはほかの目盛りと同じにする
- 世界の境目は、方眼と同じ水色の系統で少し濃く太くする（赤のインクと紛らわしくならないように）
- 世界の上のもの（ポイント）はスタンプ風、画面に固定された道具（ジョイスティック・ミニマップ）は透けない紙色の台、と質感を分ける。台はぼかし（すりガラスの効果）を使わない（効果が薄く、背景が毎フレーム動くので重くなるため）

## アクセシビリティ

絵や線は Canvas に描くので、そのままでは支援技術に何も伝わらない。見た目は変えずに、次を本番の実装で入れる（impeccable の critique で指摘）。

- 画面には見えない見出し（`h1`）で、自己紹介の文面「I'm pointp, always moving」を置く。スクリーンリーダーで、サイト名と自己紹介が読み上げられるように
- Canvas は飾りとして扱い（`aria-hidden="true"`）、内容は上の見出しで伝える
- ジョイスティックには `role` と `aria-label` を付け、何の操作かを伝える
- キーボードでは操作しない（「操作」の決まりのとおり）。マウスやタッチでジョイスティックを動かして遊ぶページだと分かる短い説明を、画面には見えない形で 1 つ置く（スクリーンリーダーが読む。Tab では選べないようにする。見えないものを選ぶと、目で見ている人には何も起きないように見えるため）
- 動きを減らす設定（`prefers-reduced-motion`）への対応は、「最初の流れ」と「ポイント」に書いたとおり

## 想定外の状況への備え

impeccable の harden で洗い出した。本番の実装で入れる。

- **2 本目の指**: ジョイスティックは最初に触れた指だけを追い、ほかの指は無視する（ノブが別の指へ飛び移らないように）
- **操作の中断**: ブラウザが操作を取り消したとき（`pointercancel`）、ポインターの捕捉が外れたとき（`lostpointercapture`）、ウィンドウやタブを離れたとき（`blur`・`visibilitychange`）は、指を離したのと同じ扱いにする（ノブを中心に戻す）
- **保存の失敗**: 紙が光るのは、画像を作れたときだけにする。作れなかったとき（`toBlob` の失敗など）は、保存のスタンプが小さく横に揺れて、何も起きなかったことを伝える（成功したように見せない）
- **ポイントを置ききれないとき**: 離す距離の条件を少しずつゆるめて、必ず 15 個置く
- **とても小さい画面**: 画面の短い辺が 300px 未満のときは、自己紹介だけを見せ、ジョイスティック・ミニマップ・ポイントは出さない（遊べる大きさがないため）。スマホの横向き（高さ約 390px）は遊べる大きさなので対象外。開いたあとに遊べる大きさへ広がったら、そこから遊べるようにする（逆に小さくなっても、遊んでいる途中ではやめない）
- **長く遊ぶ**: 線の点は、前の点から 2px 以上進んだときだけ記録する（見た目は変わらず、点の数が大きく減る）
- **タブを裏に回す**: 裏にある間は止め、戻ったら続きから動かす（自己紹介を書く時間、手がかりの時間も同じ。戻った瞬間に一気に進まないように）
- **JavaScript が動かない環境**: 自己紹介の字（`tools/intro/build.mjs` が `html/` へ書き出す `intro.svg`）を、方眼の上の静かな絵として表示する（`noscript`）
- **localStorage が使えない環境**: 例外を握りつぶし、ジョイスティックの手がかりを毎回見せる
- **書体が読み込めない**: Georgia で「P」の文字を描き、読み込めたら描き直す

## 描画の方針

数値は机上の見積もり。本番の前に実機で測って調整する。

- 線は座標のデータとして持つ。世界全体の大きさの画像は持たない
- 表示用のキャンバスは 1 枚にし、`getContext('2d', { alpha: false })` で作る。毎フレーム、方眼 → 区画の画像 → スタンプ → 点P → 「P」の文字の順に描く（背景が毎フレーム動くので、層を分けても描き直す量は減らない）
- 本画面の線は、世界を区画に分け、画面に映る区画だけを画像として持ち、新しい線はそこに描き足す
  - 区画の大きさは、世界の 1 辺をちょうど割り切る 256px 前後（世界の 1 辺 ÷ ceil(1 辺 ÷ 256)。例: 2160 → 240px、4080 → 255px）。割り切れると、端をまたいだ写しにも同じ画像を使い回せる。512px より、スマホでメモリが 4〜6 割減る
  - 区画の画像の解像度は devicePixelRatio 2 までにする（6〜24px の線なら 3 との差はほとんど見えない）。画素数は整数に丸め、描く位置もデバイス px に丸める（区画の継ぎ目に細い筋が出ないように）
  - 区画には線だけを描き、背景は透明にする。方眼は毎フレーム描く
  - 画面の外へ区画 1 枚分以上離れたら捨てる。保持する上限は「画面に映る最大枚数 × 1.5」とし、超えたら最後に映った時刻が古い順に捨てる。捨てたキャンバスは使い回し、あふれた分は width・height を 0 にする（iOS Safari はメモリをなかなか返さないため）
  - まだできていない区画は、座標データから直接描く。区画を作るのは 1 フレームに約 4ms までにし、画面の中心と進む向きに近い区画から作る
  - 自己紹介を書いている間とカメラが寄る 1 秒の間は、区画を使わず、座標データから毎フレーム直接描く（引いた状態で区画を使うと世界全体分の区画が要り、寄っている間は倍率が変わるので 1 枚の画像にも描き足せないため。約 5,000 点なので軽い）。寄り終わった付近の区画は、寄っている間の空いた時間に作っておく
  - 端をまたいで描くときは、画面に映る範囲を区画の番号に直し、世界の区画数で割った余りの区画を描く（9 枚分は描かない）
- 線の色は不透明だけにする（描き足していくので、半透明だと重なった所が濃くなる）
- 線の座標データ
  - Float32Array のかたまり（4096〜16384 点ごと）で持ち、足りなくなったら足す。色・太さ・端をまたいだ切れ目は、別の小さな配列に「何番目の点から」で持つ
  - 向きが変わらない間は、新しい点を足さず最後の点を動かす（直進の間は点が増えない）
  - 進行中の線（最後に描き足した点から今の点P まで）は、区画に描かず毎フレーム上に重ねて描く。点が 32 個たまったとき、色や太さが変わるとき、端をまたぐときに、1 本のパスとして区画とミニマップに描き足す（毎フレーム描き足すと、同じふちを何度も塗ってふちが濃くなり、作り直した絵と変わるため）
  - 区画ごとに、その区画を通った点の範囲の目次を持つ（区画の作り直し・全消去の演出・PNG 保存で、全部の点を調べずに済むように）
  - 点の数の上限は 200 万点（16MB）。超えたら古い線から消し、その区画は作り直す（いちばん速く、ずっと向きを変え続けても約 2.7 時間かかる量。念のための安全策）。目次は番号をずらすだけにし、ミニマップは裏で数フレームかけて描き直してから差し替える（1 フレームで止まらないように）
- 全消去の演出: 消した瞬間のデータ・目次・区画を「消えていく線」として 0.5 秒だけ残し、画面に映る範囲だけを点線で描く。画面に映る点が多いとき（目安 3 万点超）は、点線をやめ、古い区画の画像を薄くするだけにする
- ミニマップ: 線の画像と、点P・見えている範囲の枠・ポイントを、キャンバスを分けて重ねる。線の画像は新しい分だけ描き足し、上の層だけを毎フレーム描き直す。全消去や表示サイズの変更のときだけ、座標データから描き直す。線は最小 1px にする。自己紹介を書いている間は描かない
- スタンプ 11 種類は、前もって小さな画像にしておき、毎フレームは回して貼るだけにする
- 毎フレーム、新しい配列やオブジェクトを作らない（ガベージコレクションで止まらないように）
- 時間
  - ゲームの中の時計を 1 つだけ持ち、毎フレーム前のフレームからの時間（0.1 秒まで）を足す。自己紹介・手がかり・全消去・スタンプの沈み・保存の光など、すべての時間をこの時計で測る（タブから戻ったときに一気に進まないように）
  - 動きも減衰もすべて時間で計算する（120Hz の画面でも速さが同じになるように）。フレームレートは抑えない
  - ポイントの当たり判定は、前のフレームの位置から今の位置までの線分と円で行う（間隔が長いフレームでも飛び越さないように）
  - タブが裏にあるときは `visibilitychange` でループを止め、戻ったら前回の時刻を今にそろえる
  - 長い時間触られなくても、そのまま動き続ける（「Always moving」のとおり。直進の間は点が増えないので、データも増えない）
- ジョイスティックの見た目（目盛りの色・ノブ）は、変わったときだけ書き換える。ノブは CSS の transform で動かす
- リサイズしたとき:
  - キャンバスの大きさを変えると描いた内容が消えるため、直後に区画の画像を並べ直す（一瞬白くならないように）
  - 新しく映る区画は座標データから描く。一度に多いときは、画面の中心に近い区画から数フレームに分けて描く（カクつかないように）
  - devicePixelRatio が変わったとき（ブラウザの拡大縮小、解像度の違うモニターへの移動）は、区画の画像をすべて新しい解像度で描き直す（ぼやけないように）
- PNG 保存
  - CSS px と同じ解像度（1 倍）で書き出す。世界の大きさの上限は 4096 前後にし、iOS Safari のキャンバスの面積の上限（約 1,677 万 px）に収める
  - 保存を押した時点の点の番号を覚えておき、そこまでの線を 1 フレーム約 4ms までずつ、数フレームに分けて描く（点P を止めないように）。方眼は 120px 四方の模様を敷いて描く
  - 終わったら、保存用のキャンバスを width・height を 0 にして手放す。ダウンロードのあと、少し遅らせて `URL.revokeObjectURL` する
  - 保存している間に、もう一度保存のポイントを通っても無視する
  - 画像を書き出す（`toBlob`）のに 0.3〜2 秒かかるので、紙が光るのは、スタンプを押してから少しあとになる（押した瞬間の反応はスタンプの沈みで出す）
- キャンバスの中身が失われたとき（`contextlost`・`contextrestored`、裏から戻ったら中身が消えていたとき）は、区画とミニマップを座標データから作り直す。裏から戻ったときと、点の上限で古い線を消したときは、区画を捨てずに見せたまま数フレームかけて描き直す（線が長いときに引っかからないように）。区画のキャンバスを作れなかったとき（`getContext` が null）は、古い区画を捨て、解像度を 1 倍に下げて作り直す

## 言語と検索・SNS

- 言語は英語にする（`<html lang="en">`）。見えない見出し・説明・title・description もすべて英語（画面の文字が英語なので、スクリーンリーダーが英語の音声で読むように）
- title は `pointp.dev`。description は英語で 1 文
- canonical は `https://pointp.dev/`（末尾のスラッシュ付き）
- OGP: `og:type`（website）・`og:title`・`og:description`・`og:url`・`og:image`（絶対 URL、1200×630 の PNG）・`og:image:alt`・`og:site_name`（pointp.dev）と、`twitter:card`（summary_large_image）
- OGP 画像は、方眼の紙に自己紹介の字を描いたもの。作り直したらファイル名を変える（SNS 側が古い画像を長く覚えているため）
- robots.txt と sitemap は置かない（1 ページだけで、ないと全部許可と同じ扱いになる）
- アイコンは `favicon.svg`・`favicon.ico`（32px）・`apple-touch-icon.png`（180px）。図柄は紙の色に Black の点P と斜体の「P」。`favicon.ico` は必ず置く（ブラウザが自動で取りに来るので、ないと毎回 404 になる）
- manifest と Service Worker は作らない（PWA にする目的がない）
- 持ち主の名前・連絡先は、どこにも出さない（HTML・OGP・画像のメタデータを含む）

## 対応する環境

- Chrome・Edge 111 以上、Firefox 113 以上、Safari・iOS Safari 15.4 以上。それより古い版では崩れてもよい（足りない機能を JS で調べて分岐はしない）
- color-mix は使わず、トークンの値をあらかじめ計算しておく（対応の下限を Safari 15.4 まで下げるため）
- OffscreenCanvas と Worker は使わない（区画は通常のキャンバスで足りる）
- `100vh` を先に書いてから `100dvh` で上書きする
- viewport は `width=device-width, initial-scale=1, viewport-fit=cover`（`viewport-fit=cover` がないと safe-area の値が 0 になり、ノッチ・ホームバーを避けられない）
- `touch-action: none` と `overscroll-behavior: none` を付け、body はスクロールさせない（ドラッグでのスクロール、引っぱって更新、ダブルタップでの拡大を起こさない）。`user-select: none`・`-webkit-touch-callout: none`・`-webkit-tap-highlight-color: transparent` を付ける（長押しのメニューやタップの青い枠を出さない）
- iOS のピンチでの拡大は止められないので、受け入れる
- 画面の向きは固定しない
- OS がダークモードでも紙の色のままにする（`<meta name="color-scheme" content="light">`、`:root { color-scheme: light }`）。`theme-color` は紙の色（`#fdfdfc`）
- 印刷するときは、ジョイスティックとミニマップを隠す
- アプリ内ブラウザ（X・Instagram・LINE など）では、保存のダウンロードが黙って失敗することがあり、JS から気づけない。これは受け入れる

## セキュリティとプライバシー

- 配信するのは `html/` だけ（compose のマウントのとおり）。秘密の情報は `html/` に置かない
- インラインのスクリプト・スタイルを使わない（HTML に `style=""` 属性も書かない）。JS から `element.style` やカスタムプロパティを変えるのはよい
- 文字列から HTML を作る処理（`innerHTML` など）を使わない
- アイコンは Canvas の Path2D で描き、画像を Canvas に描かない（CSP を狭くでき、`toBlob` の失敗も避けられる）
- PNG には、日時のファイル名以外の情報を入れない
- 第三者のスクリプトは読み込まない。アクセス解析・Cookie・広告・SNS の埋め込みは使わない（同意の表示やプライバシーポリシーも要らない）
- localStorage は、ジョイスティックに触ったかどうかの 1 キーだけにする。`"1"` 以外の値は「まだ触っていない」として扱う
- 「P」の文字の書体（STIX Two Text）は、「P」1 文字だけに絞った woff2 を自前で配信する（Google へ閲覧者の情報が送られないように。CSP も自分のサイトだけで済む）。SIL OFL のライセンス文を一緒に置く。Reserved Font Name があれば、絞った版の中のフォント名を変える
- セキュリティヘッダーは Nginx で付ける。`always` を付けて 404 などにも付ける。HSTS だけは Cloudflare で付ける
  - Content-Security-Policy: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'`
  - `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`、`Cross-Origin-Opener-Policy: same-origin`、`Cross-Origin-Resource-Policy: same-origin`
  - `Permissions-Policy: accelerometer=(), camera=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), payment=(), usb=(), browsing-topics=()`
  - Nginx の `add_header` は、location の中に 1 つでもあると server の分を引き継がない。共通のヘッダーは別のファイル（拡張子は `.conf` 以外。`conf.d/*.conf` は自動で読み込まれるため）にまとめ、各 location で `include` する
  - CSP は、まず `Content-Security-Policy-Report-Only` として `compose.dev.yaml` で確かめ、違反が出ないことを確かめてから本番に切り替える
- HSTS（Cloudflare）: `max-age=31536000; includeSubDomains`。preload は付けない（`.dev` は TLD ごと preload 済み）。Always Use HTTPS をオン、Minimum TLS は 1.2
- Nginx: GET と HEAD 以外は 405 を返す。隠しファイル（`/.` で始まるパス。`/.well-known/` を除く）は 404 を返す。404 ページは自前の `404.html` を出す
- Cloudflare で、ページにスクリプトを差し込む機能（Rocket Loader・Email Obfuscation・Web Analytics の自動設定・Zaraz・Bot Fight Mode の JS challenge）は切る
- アクセスログは残すが、容量に上限を付ける（compose の `logging.options.max-size`）
- security.txt は置かない（連絡先を出さないため）

## 読み込みとキャッシュ

- 目標
  - 最初の 1 フレームを出すまで、外部のサイトには取りに行かない
  - 初回の転送量は、HTML・CSS・JS・自己紹介のデータを合わせて圧縮後 50KB 以下（目安は 30KB。アイコンと OGP 画像は数えない）
  - JS が動き始めてから最初のフレームまでの処理は、中くらいのスマホ（DevTools の CPU 4 倍遅延）で 50ms 以下
  - 書き始めまでの時間は、Lighthouse のモバイル設定（Slow 4G）で 1.5 秒以下、PC の光回線で 0.5 秒以下。Canvas は LCP の対象にならないので、書き始めの瞬間に `performance.mark('intro-start')` を打って測る
- 最初のフレームまでにするのは、世界の大きさ、自己紹介の倍率と位置、カメラの引き具合の計算と、方眼・点P の描画だけ。ポイントの配置、スタンプの画像、ミニマップ、書き終わり付近の区画は、書いている 5 秒の間に後回しにする（`requestIdleCallback`、ない環境では `setTimeout`）
- 書き始めは、`load` もフォントも待たない。DOM ができた直後の最初の `requestAnimationFrame` から時計を動かす
- 「P」の文字の書体は `<head>` で読み込まず、最初のフレームのあとに読み込む（CSS の `@font-face` で書体を定義し、JS から `document.fonts.load()` で読み込みを始める。書体のファイル名のハッシュは esbuild が CSS に入れる）（書き終わるまで 5 秒あるので間に合う）
- CSS で `html { background: #fdfdfc }` を最初に効かせる（JS が動く前に白や黒の画面が一瞬出ないように）
- 自己紹介のデータ: `tools/intro/build.mjs` が、点P が描くための曲線のデータを JS として書き出す。実行時に、曲線を数行のコードで折れ線にし、長さの累計の表を作る（405 本の曲線で 1ms 未満）。`getPointAtLength` は使わない（重く、Safari では特に遅い）。小数は 1 桁に丸める（誤差は 0.25px 未満）
- `noscript` 用の `intro.svg` も `html/` へ書き出す（今の `tools/intro/` は配信されない）。線の太さは、本画面と比が合うよう約 2.6（viewBox の単位）にする
- キャッシュ
  - JS・CSS・書体はファイル名に中身のハッシュを入れ（例: `main.3f9a2c1b.js`）、`Cache-Control: public, max-age=31536000, immutable` にする
  - HTML は今のまま、ブラウザは毎回確認し、Cloudflare は 5 分（`max-age=0, s-maxage=300`）
  - 画像・アイコンは今のまま 1 日。OGP 画像は作り直したらファイル名を変える
  - Cloudflare が HTML をキャッシュするかは、Cloudflare のキャッシュルールの設定による（katarina-infra の docs/cloudflare/cache.md で確かめる）
  - デプロイしたら、Cloudflare のキャッシュを消す（Purge Everything）
- 圧縮・HTTP/2・HTTP/3 は Cloudflare に任せる（Nginx の gzip は入れない）
- JS の拡張子は `.js` にする（`.mjs` は Nginx の MIME タイプとキャッシュの設定で扱えない恐れがある）

## ビルドと依存関係

- ビルドには esbuild を使う（開発時だけ。依存を少なくして、脆弱性の見直しを軽くするため）。依存は esbuild だけにする
- 書いたソースは `src/` に置き、ビルドの結果を `html/` へ書き出す。`html/` の中身は手で編集しない
  - esbuild で JS と CSS をまとめ、ファイル名にハッシュを入れる
  - HTML の中のファイル名の書き換えは、Node の標準機能だけで書いた小さなスクリプトで行う
  - 書き出す前に、前回のハッシュ付きのファイルを消す
- アイコンと OGP 画像は `tools/assets/build.mjs`（`npm run assets`）で、Chrome のヘッドレスを使って作り、`src/public/` へ書き出す（開発時だけ）
- 書体は、STIX Two Text の斜体 600 を Google Fonts から「P」1 文字だけに絞って取り出したもの（約 1KB）。CSS の中の書体名はサイト独自の名前（`pointp P`）にする（STIX Fonts は IEEE の商標のため。予約されたフォント名は「TM Math」だけで、対象外）
- `package-lock.json` をコミットし、`npm ci` で入れる（いつも同じ版が入るように）
- 開発中の確認用サーバー（esbuild の serve）は、自分の PC の中だけで動かす（ネットワークへ公開しない）。書き出し先は `.dev/`（Git に入れない）にし、コミットする `html/` を汚さない。スマホの実機で確かめるときは、ビルドした `html/` を `compose.dev.yaml` の Nginx で配信する
- Dependabot に npm を足し、脆弱性の修正と新しい版をプルリクエストで受け取る。GitHub の Dependabot alerts もオンにする
- GitHub Actions を使うようになったら、Dependabot に `github-actions` も足す
